# Testing and verification

[Documentation index](../README.md#documentation)

## Default checks: no keyboard required

```powershell
.\build.ps1 -TestsOnly
```

The current suite reports **63 protocol/profile assertions**. It checks:

- Twenty effect payloads, UserDefine active/stored-record differences and custom Caps RGB.
- The complete independently captured key-index lookup, not just a few examples.
- Disabled, keyboard/modifier, chord and repeated-macro binding payloads.
- Macro offsets, event tags, implicit delays and sentinels against a vendor capture.
- Gaming flags, invalid effects/keys/RGB and complete profile schema requirements.
- UTF-8 file-size limits, Unicode round trips and preservation on rejected saves.
- Recording release completion/budgets, device collection/container matching and
  acknowledged-section state comparisons.
- ACK shape, rejection recovery, stale/zero responses and the one-retry limit.

Temporary profile files are generated by the tests. HID methods are compiled but
the default suite does not call discovery or device writes. The build also
compiles `DeviceCheck.exe`; merely compiling that helper does not execute it.

## Independent fixtures

[`tests/fixtures`](../tests/fixtures/README.md) contains exported payload bytes
from the original serializers using artificial settings with outgoing writes
blocked. The exporter removes unused buffer tails and excludes device paths,
addresses, real user data and executable code. `manifest.json` identifies the
source artifact and payload digests. The suite compares the new serializers
with independent observations rather than using them to compute expected results.

## Native UI checks: writes to a keyboard

```powershell
.\build.ps1 -NativeChecks
```

The last development run reported **36 native UI assertions**. It exercises the
real WPF classes and worker code, including:

- Device discovery, feature tabs and per-effect controls.
- Detached assignment drafts, accepted nonphysical HID destinations and retained
  local-profile targets.
- Macro deletion/slot refresh, safe refusal of an unfinishable recording, and
  reopening a macro too large for device upload.
- Invalid input blocking, device-selection disabling during Apply, and a new
  profile retaining pending edits when an older request completes.
- Real lighting Apply and restoration of the declared test brightness.
- Native screenshots and compact-window layout.

The test isolates profile persistence. It deliberately changes hardware lighting
and does not establish an unknown original hardware backup. Generated screenshots
go into ignored `evidence/`; an interactive Windows desktop and matching keyboard
are required. GitHub-hosted CI runs only the default hardware-free build.

## Discovery helper and application CLI

`dist/DeviceCheck.exe` with no arguments performs discovery. Its `--light` mode
sends settings and is a development helper, not a read-only inspection command.
Prefer the documented [application CLI](TROUBLESHOOTING.md#command-line-diagnostics)
for normal diagnostics and explicit profile application.

## What has actually been observed

On the connected development keyboard, Static, Breath and retained Scrolling
profiles produced successful complete transactions, ordinarily **22 writes and
4 matching positive command ACKs**. The packaged app's CLI and native UI were
both exercised. An intermittent matching `FF` rejection was observed; a bounded
resend matching the original helper's policy was added and covered by checks.

| Evidence | Establishes | Does not establish |
| --- | --- | --- |
| Source/manual | Intended capabilities and control availability | Every physical revision behaves identically |
| Golden payload match | New serializer matches controlled original bytes | Hardware has executed the setting |
| Matching device ACK | Protocol operation accepted | Exact LED appearance, key output or retention after power loss |
| Native UI test | Actual editor/Apply path operates on the connected device | Every macro/host-action path was manually exercised |
| Physical/power-cycle test | Only the specific observed behavior | Untested modes/revisions |

Complete settings readback, all playback paths and power-cycle retention remain
open validation work. A passing hosted workflow is not a hardware certification.
